# Entity — `CommunityPost`

## Purpose

A `CommunityPost` is one entry on the athlete-portal community feed (#600, M9 community layer). Parent table for reactions, comments, and RSVPs. Post types (`App\Enums\CommunityPostType`):

- **`belt_promotion`** — auto-generated by `AthleteObserver` on `athletes.belt` change (PR-B).
- **`stripe_promotion`** — auto-generated by `AthleteObserver` on a stripes change (post-v2.9.0).
- **`event`** — owner-created event post with date + location (PR-E).
- **`owner_announcement`** — reserved enum slot for V1 follow-up / V2.
- **`shared_video`** — an athlete or owner shares an external technique video (Instagram / YouTube / TikTok) into the feed (#1153). The first feed type athletes can author. Payload + flow: [`docs/specs/community-video-share.md`](../specs/community-video-share.md).

V2-forward: `visibility` already supports `'public'` for the cross-academy + mappa feature; V1 always inserts `'academy'`. The shape of `payload` varies by `type` — see [`docs/specs/m9-community.md`](../specs/m9-community.md) § Tech decisions.

## Schema — `community_posts`

| Column | Type | Constraints | Purpose |
|---|---|---|---|
| `id` | bigint unsigned | PK, auto-increment | Internal identifier |
| `academy_id` | bigint unsigned | not null, FK → `academies.id` ON DELETE CASCADE | Single-academy scope (V1 hard rule). Cascade matches the 30-day purge path. |
| `type` | string(32) | not null | One of `belt_promotion` / `stripe_promotion` / `event` / `owner_announcement` / `shared_video`. Stored as string (SQLite-portable); enum validation in the Eloquent cast + FormRequest. |
| `visibility` | string(32) | not null, default `'academy'` | V1 always `'academy'`. `'public'` is the V2 cross-academy slot. |
| `payload` | json | not null | Per-type payload — see PRD § Tech decisions. Cast as `array` on the model. |
| `created_by_user_id` | bigint unsigned | not null, FK → `users.id` ON DELETE CASCADE | Author. For `belt_promotion`: the owner who triggered the change. For `event`: the owner who created it. |
| `created_at` | timestamp | nullable | |
| `updated_at` | timestamp | nullable | |
| `deleted_at` | timestamp | nullable | Owner-only soft-delete for moderation. |

### Indices

- `INDEX (academy_id, deleted_at, created_at)` — covers the feed-page hot path `WHERE academy_id = ? AND deleted_at IS NULL ORDER BY created_at DESC LIMIT 20` index-only.

## Relations

- `belongsTo(Academy::class)` — tenant scope.
- `belongsTo(User::class, 'created_by_user_id')` — author.
- `hasMany(PostReaction::class, 'post_id')` — clap/pray reactions (V1).
- `hasMany(PostComment::class, 'post_id')` — threaded comments (V1).
- `hasMany(PostRsvp::class, 'post_id')` — event RSVPs (only meaningful when `type = 'event'`).

## Business rules

- **Single-academy scope (V1)** — every read query filters by `academy_id`. Writes 422 / 403 across academies.
- **Owner-only soft-delete (moderation)** — athletes cannot delete posts; the owner can. Hard-delete only via academy cascade.
- **`belt_promotion` is fan-out-only** — created by `AthleteObserver`, not by any HTTP endpoint. Athletes can't create promotion posts manually.
- **`shared_video` is the only athlete-authorable type (#1153)** — created via `POST /community/videos` by any academy member (athlete, or staff with `CommunityFeedInteract`). The server resolves the preview from an **allowlisted provider** (Instagram / YouTube / TikTok); that host allowlist is also the SSRF boundary for the server-side fetch. Post-moderated (owners delete). Stored payload: `{ provider, url, video_id, thumbnail_path?, title?, author_name?, caption? }` — the cover image is cached on our `public` disk (`thumbnail_path`) so the facade renders it first-party; `CommunityPostResource` projects it as a same-origin `thumbnail_url` (#1155), and the internal path is not exposed.
- **Payload shape is per-type** — the `CommunityPostType` enum is the source of truth; new types require a new enum case + payload-shape doc.
