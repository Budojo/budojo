# v2.31.0 — 2026-05-24

A full-codebase audit + cleanup train. Three user-visible upgrades on the athletes list, one big i18n unblock, plus a security + Clean-Architecture sweep behind the scenes.

## 🥋 Athletes list: avatars, expanded quick-actions, i18n

Three usability wins on the athletes roster, both desktop and mobile:

- **Avatars** next to every name — the photo from the athlete's profile if uploaded, otherwise a circular initials placeholder ("MR" for "Mario Rossi"). Tap the avatar to jump straight to that athlete's public profile when they have a handle.
- **Expanded ⋮ menu** on the mobile cards — now includes Attendance, Documents (with the medical certificate inside), Payments (when the academy tracks fees), Belt history, and Public profile, alongside the existing Edit + Delete. The single quick destination you needed three taps for is now one.
- **Upload-document dialog fully localized** in Italian — labels, validation errors, button text and toast messages. The dialog was the largest remaining EN-only screen.

## 🛡️ Security hardening

A focused security pass closes a dozen findings at once:

- **2FA endpoints rate-limited** to 5 requests/minute per user — closes the brute-force window on the 6-digit TOTP code and on the password gate that disables 2FA. Hits 429 with Retry-After if you burn the budget.
- **Web Push device secrets are now encrypted at rest** — the per-device `auth` salt and the bearer URL are stored as ciphertext; a hypothetical DB dump can no longer be used to forge or decrypt pushes.
- **Rate-limits added** on `/me/avatar` upload (10/min), `/me/api-tokens` mint (10/min), `/me/push-subscriptions/test` (5/min) — caps the storage-flood, token-loop and vendor-fanout vectors.
- **Security headers on every API response** — HSTS, X-Frame-Options DENY, CSP (`default-src 'none'` + `form-action 'none'` + `base-uri 'none'`), Referrer-Policy no-referrer, X-Content-Type-Options nosniff. Belt-and-suspenders so dev / staging / future container deploys ship the same hardening as production nginx.
- **CORS allowlist tightened** — `allowed_methods` and `allowed_headers` now enumerate the verbs and headers the SPA actually uses, instead of `['*']`.
- **Password fields capped at 255 chars** on all seven login / register / reset / change / accept-invite / disable-2FA / delete-account endpoints — defends against bcrypt-cost-12 CPU-grind on multi-MB password POSTs.

## 🧪 Under the hood

Backend cleanup sprint completed — 9 controllers refactored into FormRequests + dedicated Actions following the Uncle Bob canon:

- `LoginController` → `VerifyTwoFactorAction`
- `AthleteController::{store,update}` → `CreateAthleteAction` + `UpdateAthleteAction` + new `AddressIntent` value object (replaces flag-argument antipattern with a discriminated three-way intent)
- `ActiveAcademyController::update` → `SwitchActiveAcademyAction` with discriminated result type (replaces sentinel-exception control flow)
- `OnboardingController`, `ApiTokenController`, `PushSubscriptionController`, `TwoFactorController` (confirm + destroy), `NotificationPreferencesController` → dedicated FormRequests, transaction logic moved into Actions.

Test coverage filled in: 4 unit specs for the new Actions + new value object, 8 PEST regression tests for the password-cap security guarantee, 3 PEST tests for the security headers middleware, 3 PEST tests for the throttle caps, vitest spec for `LeaderboardService` (gap from v2.30.0).

Documentation drift recovery: 4 entity docs added for the M9 community tables (post + reaction + comment + RSVP), `m5-notifications` PRD flipped to "Shipped", 8 missing routes added to `docs/api/v1.yaml`, achievement + leaderboard / recap endpoints + `users.leaderboard_visible` column documented in lock-step with the v2.30.0 features.

Frontend lint hardening: stylelint integrated with an 8dp-grid spacing rule (warning-only for now; one click-zone, one rule, future SCSS regressions surface in PR diff). Plus OnPush change-detection on Login + Register components, the two remaining outliers across the SPA.
