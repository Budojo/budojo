# v2.6.0 — 2026-05-11

Two parallel themes in this release: **stronger sign-in security** (TOTP two-factor + API tokens for scripts) and a **calmer dashboard surface** (in-app inbox + first-run checklist + browser-push plumbing). Plus a hard compliance win: medical certificates are now encrypted at rest, and old ones expire themselves on a 24-month retention cron.

## 🛡️ Two-factor authentication

Add a second step to every sign-in. From `/dashboard/profile`, open **Two-factor authentication**, scan the QR with Google Authenticator / 1Password / Authy / any TOTP app, type the 6-digit code it shows, and you're done. From the next login onwards Budojo asks for the code AFTER the password.

You also get **8 single-use backup codes** on enrolment — save them in a password manager. Each one works once if you lose your phone. The panel surfaces how many remain and lets you regenerate the set whenever you want.

Disabling 2FA requires your current password (defense in depth — a stolen session can't strip 2FA from you).

## ✨ "Getting started" checklist

Brand-new owners landing on the dashboard after academy setup now see a 5-step checklist at the top of `/dashboard/athletes`: add an athlete, log attendance, mark a payment, upload a document, view stats. Each row has a **Show me** CTA that navigates to the right feature AND ticks the step done in one tap.

The checklist self-dismisses once every step is ticked. There's also a small **Dismiss** link in the corner for owners who already know their way around — one click + confirm and it's gone for good.

## 🔔 In-app notification center

A bell icon arrives in the dashboard topbar. The unread count badges live on the bell, and tapping it opens a 20-row panel with the latest notifications. Each row deep-links to the originating object (the athlete whose certificate is expiring, the payment month you haven't ticked yet) and flips to "read" in the same click. A **Mark all read** CTA at the top bulk-flips.

The inbox surface ships today; the actual reminder fan-out (medical-cert expiry, unpaid-athletes digest) gets wired into the bell in a focused follow-up — for now the bell carries any notification produced via `$user->notify(...)` by future flows.

## 🔧 API tokens — scripted access to your data

A new **API tokens** panel on `/dashboard/profile` lets you mint long-lived bearer tokens for scripts and integrations (a nightly roster export, a CSV automation hook, etc.). Each token gets:

- A name you pick ("nightly-export-script", "zapier-bridge").
- A scoped subset of abilities — `athletes:read`, `documents:write`, `payments:read`, etc. Granting fewer is safer.
- An optional expiry window (1–730 days).

The plaintext bearer is shown **once** at creation with a copy button and a clear "save it now, you won't see it again" gate. Lost a token? Generate a new one and revoke the old.

This is the foundation for an outbound-webhooks story coming in a future release; today it's a clean way to give your own scripts read-only access without copy-pasting your password.

## 🛡️ Medical certificates encrypted at rest

Medical certificates uploaded by academy owners are **special-category health data** under GDPR Art. 9. Until v2.6.0 they sat as plain PDFs on the server disk; anyone with backup access could read them.

From this release every new medical-certificate upload is encrypted with **AES-256-GCM** before the bytes ever touch disk. The decryption happens in memory at download time — the only plaintext copy of the document leaves with the HTTPS response. The encryption key is separate from the app secret and rotatable independently.

Existing medical certificates uploaded before v2.6.0 stay plaintext; we'll re-encrypt them in a future maintenance window. The new ones are protected from day one.

## 🛡️ Auto-purge of expired medical certificates

The DPIA on medical certificates set a 24-month retention window. A new daily cron (`03:15 Europe/Rome`) now sweeps every medical certificate whose `expires_at` is more than 24 months in the past and removes BOTH the database row and the file on disk. Federation registrations and ID copies are not touched — they have different retention rules.

A user-visible benefit: the dashboard's "Expiring documents" widget no longer ages out of proportion to its usefulness. A compliance benefit: GDPR Art. 5 § 1 (e) ("kept for no longer than necessary") is now enforced by automation, not by a footnote.

## 🔧 Browser push — server-side plumbing

Behind the scenes we shipped the server half of browser push notifications: a `push_subscriptions` table per user, three endpoints on `/me/push-subscriptions` for the SPA to subscribe / list / revoke, and VAPID key configuration. The Profile toggle that calls `PushManager.subscribe()` and the actual delivery on reminder triggers land in a focused follow-up — the table waits, ready.

When that follow-up ships you'll see a "Browser notifications" toggle on `/dashboard/profile`; today the surface is invisible.
