# v2.25.0 — 2026-05-20

Two follow-ups on owner feedback after v2.24.0 plus the backend foundation for the upcoming attendance-percentage chart. The "documenti da controllare" widget now opens to a page that ALSO lists the athletes without a medical certificate (previously only the expiring docs showed up). Five more dashboard pages join the shared one-row page-header pattern from last release. And the API now exposes a per-athlete attendance summary — the chart on the athlete profile lands in the next release.

## 📋 La lista "Stato documenti" mostra anche chi non ha il certificato

Until now: the widget on `/dashboard/athletes` correctly counted both "in scadenza" AND "senza certificato", but tapping it opened a page that showed only the expiring documents. The athletes without a certificate were counted but had nowhere to be acted on.

Now: the page surfaces both lists side by side:

- **Atleti senza certificato medico** — one tappable row per athlete, links directly to their documents tab where the cert can be uploaded.
- **Documenti in scadenza** — same table as before with download + expiry status.

The header count chip combines both axes (`3 in scadenza · 6 senza certificato`) so the page matches the widget that opened it.

## 🧭 Page-header pattern extended to five more pages

v2.24.0 standardised the dashboard chrome on the five most-visited pages. This release adds five more:

- Impostazioni (settings)
- Dettaglio accademia
- Modifica accademia
- Modulo nuovo atleta / modifica atleta
- I miei documenti

Each header now reads in the same shape — eyebrow + title + (optional count chip) + (optional CTA on the right) — instead of the page-specific stacked layouts they used before. The page max-width also uses the shared `--budojo-page-content-max` token so the operative pages all wrap at the same desktop width.

The remaining edge pages (dettaglio atleta, stats, ricerca, support, aiuto, what's new, portale atleta) will follow in a subsequent release.

## 📈 Internal: API endpoint per attendance percentage chart

Backend foundation for the upcoming "% di presenze" chart that the user asked for on each athlete profile and on `/me`. `GET /api/v1/athletes/:id/attendance/summary?range=30|90|365` returns:

- attended count / expected count / rate
- a sparkline-ready series array (one entry per realized lesson day)

The "expected count" is the count of distinct dates where the academy actually held a lesson AND the athlete was already on the roster — so an athlete is never penalized for closures, cancellations, or pre-roster days. 5-minute cache per (athlete, range) since the chart is read-heavy.

The chart itself lands in the next release (frontend issue #894).
