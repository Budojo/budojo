# v2.6.1 — 2026-05-11

A polish release. One small visible fix in the email-verification flow plus a large wave of behind-the-scenes refactoring and test coverage — nothing you'll notice in the dashboard today, but the foundation for the next batch of features is meaningfully cleaner.

## 🐛 Email verify — resend button now shows you it's working

If your verify-email link expired (or got mis-clicked from another device) and you landed on the "Verification failed" page, clicking **Resend verification email** used to give you no visible feedback for the full duration of the request — the button stayed bright and clickable, the page stayed put, and you'd either get redirected (success) or see a toast (error) only at the end. Annoying enough that some people clicked twice; the app ignored the second click via an internal re-entrancy guard, but from the screen you couldn't tell.

Now: the button shows a spinner and disables itself for the whole duration of the resend request. Standard "your click registered, sit tight" feedback. One-line fix, but visible.

## 🔧 Behind the scenes — auth-chrome refactor + first test coverage on a stale corner

A handful of internal-only changes that don't touch what you see today but matter for the next batch of work landing on top:

- **`<app-verify-page>` shared component.** The three landing pages users hit after clicking a verification email — `verify-success`, `verify-error`, `verify-email-change` — used to ship three near-identical copies of the page chrome (centred icon, title, message, CTA). The chrome now lives in one shared component, with state-coloured icon variants (green / amber / red / spinner). When the M7 athlete-invite verification link arrives, it'll be a 5-line consumer of the same component instead of a fourth copy.
- **`EmailChangeController` moved out of a one-resident namespace.** The PHP-side `App\Http\Controllers\Account\` namespace had exactly one controller in it (`EmailChangeController`) — an asymmetry left over from earlier rapid feature shipping. Split it so `request` + `cancel` (authenticated `/me/*` actions) live under `User\` and `verify` (public token-based verification) lives next to the existing primary-email verify under `Auth\`. URLs unchanged.
- **`App\Actions\Account\*` redistributed the same way.** The three Actions that backed the email-change flow followed their controllers — `RequestEmailChangeAction` and `CancelPendingEmailChangeAction` to `Actions\User\`, `ConfirmEmailChangeAction` to `Actions\Auth\`. The `Account/` namespace is now empty and gone.
- **Vitest coverage on five previously-untested Angular components.** `VerifySuccessComponent`, `VerifyErrorComponent`, `AthletePortalWelcomeComponent`, `NotificationBellComponent`, `AthleteInviteComponent` all had zero unit tests before this release — only the Cypress E2E happy paths covered them. They now have proper specs (35+ tests across the five files) pinning the state machines, lifecycle hooks, branching logic, and error paths so a future refactor can't silently regress them.
- **Project board hygiene + documentation upkeep.** A backlog refinement pass assigned every issue to the right owner, ticked or cleaned every stale test-plan checkbox on closed PRs, and added two entries to `.claude/gotchas.md` (per-consumer customisation audit during shared-component extraction, and a script-flag-vs-CI-format-check trap) so the next agent / dev session doesn't trip on the same things.
- **Knowledge-graph integration.** A new `/graphify` slash command is wired into the repo — it builds a navigable graph of the codebase (3.7k nodes, 4.6k edges in the current snapshot) and the agent consults it before touching unfamiliar code. A post-commit hook keeps the graph current. Pure agent-side tooling, but it surfaced the two namespace-cleanup issues in this release as part of its diagnostic pass.

Nothing in the behind-the-scenes block is user-visible today; it shows up as faster, less-regression-prone delivery on the next visible feature.
