# v2.25.1 — 2026-05-20

Patch on top of v2.25.0: fix for the "Impossibile revocare il dispositivo" toast on the browser-notifications panel after re-enabling notifications post-deploy.

## 🛠️ Browser notifications — revoke no longer trips on a stale row

After every deploy that swaps the Service Worker, FCM (and Mozilla / Apple) rotate the push endpoint for that browser. The server's `WebPushChannel` correctly cleans up the now-dead row on the next outbound push (a cron, a test push, anything that returns 410 GONE).

But the SPA's local device list could still carry the old row until the next page refresh. Tapping × on that row hit `DELETE /me/push-subscriptions/{id}` → 404 → generic "Impossibile revocare" toast on a request that had genuinely succeeded (the row was already gone).

Fix:

- **Revoke is now idempotent on 404** — the SPA treats "already gone" as the desired outcome, removes the row from the list, fires the success toast.
- **Re-enabling notifications now reconciles** the device list against the server in the background (no loading flash), so the panel matches the actual state instead of carrying a phantom row.
